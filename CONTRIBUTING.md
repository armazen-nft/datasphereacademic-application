# Contribuindo com o Datasphere Academic

Obrigado por considerar contribuir.

## Fluxo recomendado

1. Crie uma branch a partir de `main`.
2. Faça mudanças pequenas e focadas.
3. Atualize documentação quando alterar comportamento.
4. Execute validações locais antes de abrir PR.
5. Abra PR com contexto, escopo e riscos.

## Padrões mínimos para PR

- Descrever objetivo e impacto.
- Incluir evidências de teste (comandos/saída).
- Atualizar `CHANGELOG.md` quando houver mudança relevante para usuários.
- Evitar commitar segredos (`.env`, chaves, tokens).

## Convenções

- Linguagem principal da documentação: português.
- Mensagens de commit: curtas, objetivas e orientadas à mudança.
- Priorizar correções incrementais em vez de refactors amplos sem necessidade.

## Reporte de issues

Ao abrir issue, inclua:
- contexto;
- comportamento atual;
- comportamento esperado;
- passos para reproduzir;
- logs/prints quando aplicável.
